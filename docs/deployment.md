# BOR — развёртывание Python-антибота

Первые изменения проверяются в [GitHub Actions](../.github/workflows/ci-deploy.yml). Только после положительных проверок **отдельный тестовый сервер** должен запустить образ по хешу коммита.

## До первого включения

1. Выделите сервер Linux с Docker Engine и Docker Compose; создайте каталог /srv/bor/releases и отдельного пользователя bor-deploy с необходимыми правами. Доступ к группе docker эквивалентен привилегиям root: желательно изолировать этот сервер от иных сервисов.
2. Получите отдельный токен через @BotFather и сохраните **только на сервере** в /srv/bor/.env с правами 600. Не передавайте секрет в Notion, GitHub или диалог.
3. Создайте SSH-ключ для пользователя bor-deploy, а его закрытую часть сохраните в секретах Actions:
   - BOR_DEPLOY_HOST
   - BOR_DEPLOY_USER
   - BOR_DEPLOY_SSH_KEY
   - BOR_DEPLOY_KNOWN_HOSTS (проверенный ключ сервера, строгая проверка обязательна).
4. Создайте GitHub Environment production с разрешённой веткой main, сначала с ручным подтверждением.
5. Вызовите workflow вручную (workflow_dispatch) из main, проверьте Docker, /version, /status, /guard on и прохождение CAPTCHA **в тестовой супергруппе**.
6. После живой приёмки установите переменную BOR_DEPLOY_ENABLED=true; новые успешные коммиты main будут автоматически обновлять контейнер.

Long polling не требует публичного домена/HTTPS на входе. Нельзя использовать один и тот же токен в нескольких работающих экземплярах.

## Проверка готовности и возврат старой версии

На сервере сохранены Docker-образ с SHA, Compose и скрипт установки. После обновления контейнера healthcheck вызывает Telegram getMe. Если новый контейнер не отвечает, скрипт пытается загрузить предыдущий сохранённый образ и восстановить контейнер.

Это **не полная проверка поведения антибота**; отдельно испытайте /guard, CAPTCHA, join_request, тайм-аут, перезапуск и ручное решение. Не используйте docker compose down -v — это удалит базу с настройками и активными задачами. Изменение схемы базы требует совместимых миграций и резервного копирования до обновления.

## Безопасное состояние по умолчанию

- До /guard on защиты входа нет. Новые функции антиспама и борьбы с рекламой ещё не реализованы.
- Невыясненные результаты Telegram API переводятся в состояние manual и доступны через /pending. Решения принимает администратор.
- Подключение боевой группы до положительной реальной приёмки не рекомендуется.
